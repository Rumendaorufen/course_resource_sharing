# 多级缓存架构设计文档

## 1. 项目现状分析

### 1.1 当前缓存架构
- **缓存类型**：仅使用Caffeine本地缓存
- **缓存配置**：
  - 最大容量：1000条
  - 过期时间：30分钟
  - 缓存名称：userDetails、resourceCache、courseCache、assignmentCache、submissionCache
- **配置文件**：application.yml和CacheConfig.java

### 1.2 存在的问题
1. **分布式环境下缓存不一致**：多实例部署时，各实例缓存独立，更新数据后其他实例缓存无法及时更新
2. **缓存容量限制**：单实例缓存容量有限，无法存储大量热点数据
3. **缓存穿透风险**：无有效的缓存穿透防护机制
4. **无容错机制**：缓存失效时直接访问数据库，可能导致数据库压力过大

## 2. 多级缓存架构设计

### 2.1 设计目标
- 实现Caffeine（一级缓存）+ Redis（二级缓存）的多级缓存架构
- 保证缓存数据一致性
- 提高系统响应速度和并发能力
- 增强系统容错性
- 防止缓存穿透和缓存击穿

### 2.2 架构组成

#### 2.2.1 一级缓存（Caffeine）
- **位置**：应用进程内
- **特点**：
  - 访问速度快（亚毫秒级）
  - 存储热点数据
  - 容量有限
- **配置**：
  - 最大容量：1000条
  - 过期时间：30分钟
  - 初始容量：100
  - 记录访问统计

#### 2.2.2 二级缓存（Redis）
- **位置**：独立的Redis服务器
- **特点**：
  - 分布式共享
  - 容量大
  - 访问速度较快（毫秒级）
  - 支持持久化
- **配置**：
  - 过期时间：60分钟（比一级缓存长，避免频繁回源）
  - 序列化方式：JSON
  - 连接池配置：最大连接数、超时时间等

### 2.3 缓存查询流程

```
+----------------+    +----------------+    +----------------+    +----------------+
|                |    |                |    |                |    |                |
|  客户端请求    +--->+  一级缓存      |    |  二级缓存      |    |  数据源        |
|                |    |  (Caffeine)    |    |  (Redis)       |    |  (MySQL)       |
+----------------+    +-------+--------+    +-------+--------+    +-------+--------+
                             |                         |                         |
                             | 命中？                  | 命中？                  |
                             +-------+--------+        +-------+--------+        |
                                     |                  |                  |
                                     | 是               | 是               |
                                     |                  |                  |
                                     v                  v                  |
+----------------+    +-------+--------+    +-------+--------+        |
|                |    |                |    |                |        |
|  返回结果      <----+  返回数据      <----+  返回数据      <--------+  查询数据    |
|                |    |                |    |                |        |                |
+----------------+    +----------------+    +----------------+        +----------------+
                                                                          |
                                                                          | 写入数据
                                                                          v
                                                          +----------------+    +----------------+
                                                          |                |    |                |
                                                          |  同时更新      |    |  更新一级缓存   |
                                                          |  二级缓存      +--->+  (Caffeine)    |
                                                          |  (Redis)       |    |                |
                                                          +----------------+    +----------------+
```

### 2.4 缓存更新流程

1. **数据更新时**：
   - 先更新数据源（MySQL）
   - 再更新Redis缓存
   - 最后更新Caffeine缓存
   - 如果Redis更新失败，仅更新Caffeine缓存，确保数据可用性

2. **缓存失效时**：
   - Caffeine缓存自然过期
   - Redis缓存自然过期
   - 提供手动清理缓存的接口

### 2.5 容错机制设计

1. **Redis不可用处理**：
   - 捕获Redis连接异常
   - 跳过Redis操作，直接使用Caffeine缓存
   - 记录日志，便于监控

2. **缓存穿透防护**：
   - 对查询结果为空的数据，设置空值缓存
   - 设置较短的过期时间（5分钟），避免占用过多缓存空间

3. **缓存击穿防护**：
   - 对热点数据，使用互斥锁（Redis SETNX）防止并发击穿
   - 批量加载热点数据到缓存

### 3.3 代码实现

#### 3.3.1 自定义缓存管理器

```java
@Configuration
@EnableCaching
public class MultiLevelCacheConfig {

    // Redis连接工厂
    @Bean
    public RedisConnectionFactory redisConnectionFactory() {
        RedisStandaloneConfiguration config = new RedisStandaloneConfiguration();
        return new LettuceConnectionFactory(config);
    }

    // RedisTemplate配置
    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);
        
        // 使用Jackson2JsonRedisSerializer序列化值
        Jackson2JsonRedisSerializer<Object> serializer = new Jackson2JsonRedisSerializer<>(Object.class);
        ObjectMapper mapper = new ObjectMapper();
        mapper.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
        mapper.activateDefaultTyping(LaissezFaireSubTypeValidator.instance, ObjectMapper.DefaultTyping.NON_FINAL);
        serializer.setObjectMapper(mapper);
        
        template.setValueSerializer(serializer);
        template.setKeySerializer(new StringRedisSerializer());
        template.setHashKeySerializer(new StringRedisSerializer());
        template.setHashValueSerializer(serializer);
        template.afterPropertiesSet();
        
        return template;
    }

    // Caffeine配置
    @Bean
    public Caffeine<Object, Object> caffeineConfig() {
        return Caffeine.newBuilder()
                .expireAfterWrite(30, TimeUnit.MINUTES)
                .initialCapacity(100)
                .maximumSize(1000)
                .recordStats();
    }

    // 自定义多级缓存管理器
    @Bean
    public CacheManager cacheManager(Caffeine<Object, Object> caffeine, RedisTemplate<String, Object> redisTemplate) {
        // 使用自定义的多级缓存管理器
        return new MultiLevelCacheManager(caffeine, redisTemplate);
    }
}
```

#### 3.3.2 多级缓存管理器实现

```java
public class MultiLevelCacheManager implements CacheManager {
    
    private final ConcurrentMap<String, Cache> cacheMap = new ConcurrentHashMap<>();
    private final Caffeine<Object, Object> caffeine;
    private final RedisTemplate<String, Object> redisTemplate;
    
    public MultiLevelCacheManager(Caffeine<Object, Object> caffeine, RedisTemplate<String, Object> redisTemplate) {
        this.caffeine = caffeine;
        this.redisTemplate = redisTemplate;
    }
    
    @Override
    public Cache getCache(String name) {
        return cacheMap.computeIfAbsent(name, cacheName -> new MultiLevelCache(cacheName, caffeine, redisTemplate));
    }
    
    @Override
    public Collection<String> getCacheNames() {
        return cacheMap.keySet();
    }
}
```

#### 3.3.3 多级缓存实现

```java
public class MultiLevelCache implements Cache {
    
    private final String name;
    private final com.github.benmanes.caffeine.cache.Cache<Object, Object> caffeineCache;
    private final RedisTemplate<String, Object> redisTemplate;
    private static final long REDIS_EXPIRE_TIME = 60 * 60; // 60分钟
    
    public MultiLevelCache(String name, Caffeine<Object, Object> caffeine, RedisTemplate<String, Object> redisTemplate) {
        this.name = name;
        this.caffeineCache = caffeine.build();
        this.redisTemplate = redisTemplate;
    }
    
    @Override
    public String getName() {
        return name;
    }
    
    @Override
    public Object getNativeCache() {
        return caffeineCache;
    }
    
    @Override
    public <T> T get(Object key, Class<T> type) {
        // 1. 查询一级缓存
        Object value = caffeineCache.getIfPresent(key);
        if (value != null) {
            return type.cast(value);
        }
        
        // 2. 查询二级缓存
        try {
            String redisKey = generateRedisKey(key);
            value = redisTemplate.opsForValue().get(redisKey);
            if (value != null) {
                // 回填一级缓存
                caffeineCache.put(key, value);
                return type.cast(value);
            }
        } catch (Exception e) {
            // Redis查询失败，记录日志，继续执行
            log.error("Redis查询失败: {}", e.getMessage());
        }
        
        return null;
    }
    
    @Override
    public <T> T get(Object key, Callable<T> valueLoader) {
        // 1. 查询一级缓存
        Object value = caffeineCache.getIfPresent(key);
        if (value != null) {
            return (T) value;
        }
        
        // 2. 查询二级缓存
        try {
            String redisKey = generateRedisKey(key);
            value = redisTemplate.opsForValue().get(redisKey);
            if (value != null) {
                // 回填一级缓存
                caffeineCache.put(key, value);
                return (T) value;
            }
        } catch (Exception e) {
            // Redis查询失败，记录日志，继续执行
            log.error("Redis查询失败: {}", e.getMessage());
        }
        
        // 3. 查询数据源
        try {
            value = valueLoader.call();
            if (value != null) {
                // 同时写入一级和二级缓存
                caffeineCache.put(key, value);
                try {
                    String redisKey = generateRedisKey(key);
                    redisTemplate.opsForValue().set(redisKey, value, REDIS_EXPIRE_TIME, TimeUnit.SECONDS);
                } catch (Exception e) {
                    // Redis写入失败，仅记录日志，不影响主流程
                    log.error("Redis写入失败: {}", e.getMessage());
                }
            }
            return (T) value;
        } catch (Exception e) {
            throw new ValueRetrievalException(key, valueLoader, e);
        }
    }
    
    @Override
    public void put(Object key, Object value) {
        // 同时写入一级和二级缓存
        caffeineCache.put(key, value);
        try {
            String redisKey = generateRedisKey(key);
            redisTemplate.opsForValue().set(redisKey, value, REDIS_EXPIRE_TIME, TimeUnit.SECONDS);
        } catch (Exception e) {
            // Redis写入失败，仅记录日志，不影响主流程
            log.error("Redis写入失败: {}", e.getMessage());
        }
    }
    
    @Override
    public void evict(Object key) {
        // 同时删除一级和二级缓存
        caffeineCache.invalidate(key);
        try {
            String redisKey = generateRedisKey(key);
            redisTemplate.delete(redisKey);
        } catch (Exception e) {
            // Redis删除失败，仅记录日志，不影响主流程
            log.error("Redis删除失败: {}", e.getMessage());
        }
    }
    
    @Override
    public void clear() {
        // 清空一级缓存
        caffeineCache.invalidateAll();
        // 清空二级缓存（使用Redis的keys命令，生产环境谨慎使用）
        try {
            Set<String> keys = redisTemplate.keys(name + ":*");
            if (keys != null && !keys.isEmpty()) {
                redisTemplate.delete(keys);
            }
        } catch (Exception e) {
            // Redis清空失败，仅记录日志，不影响主流程
            log.error("Redis清空失败: {}", e.getMessage());
        }
    }
    
    private String generateRedisKey(Object key) {
        return name + ":" + key.toString();
    }
}
```

## 6. 风险评估

### 6.1 潜在风险
1. **Redis性能瓶颈**：高并发场景下Redis可能成为性能瓶颈
2. **网络延迟**：跨网络访问Redis可能引入额外延迟
3. **数据序列化问题**：复杂对象序列化可能导致性能问题或序列化失败

### 6.2 应对措施
1. **优化Redis配置**：合理配置Redis连接池和内存策略
2. **使用本地缓存缓解压力**：热点数据优先从Caffeine读取
3. **选择高效的序列化方式**：使用Jackson2JsonRedisSerializer，避免使用Java序列化
4. **实现Redis集群**：高并发场景下考虑使用Redis集群

## 7. 总结

本设计方案实现了Caffeine（一级缓存）+ Redis（二级缓存）的多级缓存架构，通过合理的缓存查询和更新策略，保证了缓存数据的一致性，提高了系统的响应速度和并发能力，增强了系统的容错性。该方案适用于分布式部署的课程资源共享平台，能够有效解决当前系统存在的缓存一致性问题和性能瓶颈。
